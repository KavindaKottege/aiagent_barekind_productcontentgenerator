    ```python
    from pydantic import BaseModel, Field
    from typing import Literal

    class AIReviewResult(BaseModel):
        """Structured AI review result with safety checks."""

        recommendation: Literal["approve", "reject"] = Field(
            description="Whether to approve or reject the generated content"
        )
        reason: str = Field(
            max_length=200,
            description="Brief reason for recommendation (max 2 lines)"
        )
        safety_flags: list[str] = Field(
            default_factory=list,
            description="List of safety concerns: quantity_confusion, misleading_expectations, misrepresentation"
        )
        accuracy_score: float = Field(
            ge=0.0, le=1.0,
            description="Accuracy score from 0.0 to 1.0"
        )

    class AIReviewRequest(BaseModel):
        """Request for single product AI review."""
        product_group_id: str

    class BatchAIReviewRequest(BaseModel):
        """Request for batch AI review."""
        client_id: str
        auto_approve: bool = False  # When True, sets review_status directly (AI-auto mode)
    ```

    **review_product method:**
    - Async method: review_product(product_group: ProductGroup, products: list[Product]) -> tuple[AIReviewResult, Decimal]
    - Build review prompt with:
      1. Original product data (product_name, description, product_type, option_name, etc.)
      2. Generated content (generated_title, generated_description)
      3. Image URLs (for context - model can't see images but can note if they were provided)
      4. Safety check instructions (CRITICAL section)

    **Review prompt structure:**
    ```
    You are reviewing AI-generated product content for accuracy.

    ORIGINAL PRODUCT DATA:
    Product Name: {product_name}
    Description: {description}
    Product Type: {product_type}
    Option/Variant: {option_name}
    Country of Origin: {country_of_origin}
    Made to Order: {made_to_order}
    SKU: {sku}
    Images Available: {len(images)} images

    GENERATED CONTENT:
    Title: {generated_title}
    Description: {generated_description}

    CRITICAL SAFETY CHECKS (flag ANY of these):
    1. QUANTITY CONFUSION: Does the description clearly indicate if this is a single item or a set/pack?
       - Look for words like "set of", "pack of", "includes X pieces"
       - If original data suggests multiple items, generated content MUST make this clear
       - Flag if a buyer might be confused about how many items they're receiving

    2. MISLEADING EXPECTATIONS: Does the description accurately represent what the buyer will receive?
       - Check if any features are exaggerated or invented
       - Verify claims match the original product data
       - Flag if buyer expectations might not match reality

    3. MISREPRESENTATION: Does the generated title fairly represent the original product name?
       - The AI title should be an improvement, not a reinvention
       - Key product identifiers should be preserved
       - Flag if the original product identity is lost

    Evaluate the generated content and provide your recommendation.
    If ANY safety flag is triggered, you MUST recommend "reject".
    Provide a brief reason (max 2 lines) explaining your decision.
    ```

    **batch_ai_review_worker function:**
    ```python
    async def batch_ai_review_worker(ctx: dict, job_id: str, auto_approve: bool = False) -> None:
        """ARQ worker for batch AI review with progress tracking.

        Args:
            ctx: ARQ context with database session
            job_id: ReviewJob ID
            auto_approve: If True, sets review_status directly (AI-auto mode).
                          If False, only sets ai_review_status (AI-assisted mode).
        """
    ```

    **Implementation:**
    1. Get database session from context
    2. Fetch ReviewJob by job_id
    3. Update job status to "running"
    4. Query all ProductGroups for client_id with status='generated' and ai_review_status IS NULL
    5. Order by row_index for consistent processing
    6. Set job.total_count

    **Processing loop (for each product_group):**
    1. Check job status before each product (for pause/cancel)
    2. If job.status in ['paused', 'cancelled'], return early
    3. Fetch related products (for images and original data)
    4. Call AIReviewService.review_product()
    5. Update product_group:
       - ai_review_status = result.recommendation (ai_approved/ai_rejected)
       - ai_review_reason = result.reason
       - ai_review_safety_flags = result.safety_flags
       - ai_reviewed_at = now()

       **CRITICAL - AI-auto mode (when auto_approve=True):**
       - If result.recommendation == "approve":
           review_status = 'ai_approved'  # Sets final review status directly
       - If result.recommendation == "reject":
           review_status = 'ai_rejected'  # Sets final review status directly

       **AI-assisted mode (when auto_approve=False):**
       - Do NOT set review_status - user must manually approve/reject
       - Only ai_review_status is set with the AI recommendation

    6. Update job:
       - completed_count += 1
       - total_cost += cost
    7. Commit after each product

    **Error handling:**
    - try/except around each product
    - Log errors but continue processing
    - Track failed_count on job

    **Completion:**
    - Set job.status = "completed"
    - Set job.completed_at = now()
    - Commit final state

    2. Update backend/app/workers/__init__.py:
       - Add batch_ai_review_worker import

    3. Update backend/app/workers/worker_settings.py:
       - Add batch_ai_review_worker to functions list

  <action>
    Add batch AI review endpoints to backend/app/routers/review.py:

    **POST /api/review/{client_id}/ai-review/start**
    - Body: { auto_approve: bool = false }  # Controls AI-auto vs AI-assisted mode
    - Starts batch AI review for all generated products
    - Creates ReviewJob with status='pending' and auto_approve flag stored
    - Enqueues batch_ai_review_worker via ARQ with auto_approve parameter
    - Returns job_id for progress tracking
    - Blocks if active ReviewJob already exists for client

    **GET /api/review/{client_id}/ai-review/status**
    - Returns current ReviewJob status:
      - status (pending, running, completed, etc.)
      - total_count, completed_count
      - total_cost (formatted as currency)
      - auto_approve (whether in AI-auto mode)
      - Estimated remaining time (based on average)

    **POST /api/review/{client_id}/ai-review/pause**
    - Sets ReviewJob status to 'paused'
    - Worker will stop after current product

    **POST /api/review/{client_id}/ai-review/cancel**
    - Sets ReviewJob status to 'cancelled'
    - Worker will stop after current product

    **POST /api/review/{client_id}/ai-review/resume**
    - Body: { auto_approve: bool = false }  # Can change mode on resume
    - Creates new ReviewJob (like generation resume pattern)
    - Only processes products without ai_review_status
    - Preserves audit trail

    **GET /api/review/{client_id}/ai-review/progress (SSE)**
    - Server-Sent Events endpoint for real-time progress
    - Follow generation SSE pattern (500ms polling)
    - Events: progress, complete, error
    - Progress includes: completed, total, cost, status, auto_approve

    **POST /api/review/ai-single**
    - On-demand AI review for single product
    - Body: { product_group_id: UUID }
    - Calls AIReviewService.review_product directly (not background)
    - Returns AIReviewResult immediately
    - Updates product_group with AI recommendation (ai_review_status only, NOT review_status)
    - Single product review is always AI-assisted mode (recommendations only)
  </action>
