### 3. Services to Provision

**Platform-provided (already exists):**
- PostgreSQL database (shared, app uses tenant isolation via RLS)
- Next.js hosting (standard platform app deployment)

**App-provided (must be hosted):**
- Docker image: `ghcr.io/kavindakottege/madebykav_seocontentgenerator:latest`
  - Source: GitHub Container Registry, built from `backend/Dockerfile`
  - Auto-published on push to main via GitHub Actions
  - Single image serves two roles via different commands

- **FastAPI API container:**
  - Image: (same as above)
  - Command: `uvicorn app.main:app --host 0.0.0.0 --port 8000 --workers 2`
  - Port: 8000 (internal only, NOT publicly exposed)
  - Healthcheck: `curl -f http://localhost:8000/api/health` (liveness) or `curl -f http://localhost:8000/api/health/ready` (readiness)

  - Volume: `/app/uploads` -- persistent storage for uploaded Excel files
  - Needs: DATABASE_URL, REDIS_URL, SECRET_KEY, FRONTEND_URL, ENVIRONMENT

- **ARQ Worker container:**
  - Image: (same as above)
  - Command: `arq app.workers.worker_settings.WorkerSettings`
  - Port: None (background worker, no HTTP interface)
  - Healthcheck: `arq app.workers.worker_settings.WorkerSettings --check` (checks Redis health key)
  - Health intervals: 30s check, 10s timeout, 3 retries, 15s start period
  - No volume needed
  - Needs: DATABASE_URL, REDIS_URL, ENVIRONMENT

- **Redis container:**
  - Image: `redis:7-alpine`
  - Command: `redis-server --appendonly yes --maxmemory 256mb --maxmemory-policy allkeys-lru`
  - Port: 6379 (internal only)
  - Healthcheck: `redis-cli ping`
  - Volume: persistent storage for AOF data (mount at `/data`)
  - No env vars needed

### 4. Networking Requirements
- API and Worker containers must reach Redis via internal Docker networking (service name `redis`, port 6379)
- API and Worker containers must reach platform PostgreSQL (DATABASE_URL)
- API and Worker containers need outbound internet for OpenAI API calls
- API container listens on port 8000 but MUST NOT be exposed to the public internet
- Next.js must be able to reach the API container on port 8000 (internal routing)
- Next.js acts as the API gateway -- all browser requests go through Next.js, which proxies to the FastAPI API
- No container needs to be directly accessible from the public internet

<task type="auto">
  <name>Task 2: Create entrypoint script for Alembic migrations on startup</name>
  <files>backend/scripts/entrypoint.sh</files>
  <action>
Create `backend/scripts/entrypoint.sh` that runs Alembic migrations before starting the main process.

The script:
1. Runs `alembic upgrade head` to apply any pending migrations
2. Then execs the command passed as arguments (uvicorn or arq)

```bash
#!/bin/bash
set -e

echo "Running database migrations..."
alembic upgrade head

echo "Starting application..."
exec "$@"
```

Make the script executable (note this in the task for the executor).

Then update `backend/Dockerfile` to:
1. Copy the entrypoint script: `COPY backend/scripts/entrypoint.sh /app/scripts/entrypoint.sh`
2. Make it executable (before USER appuser): `RUN chmod +x /app/scripts/entrypoint.sh`
3. Set ENTRYPOINT: `ENTRYPOINT ["/app/scripts/entrypoint.sh"]`

This means:
- API container: ENTRYPOINT runs migrations, then `exec uvicorn ...`
- Worker container: ENTRYPOINT runs migrations (idempotent), then `exec arq ...`

The migrations are idempotent (Alembic tracks applied versions), so running them from both containers is safe -- the second container's migrations will be a no-op.
