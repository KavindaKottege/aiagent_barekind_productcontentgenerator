<task type="auto">
  <name>Task 2: Create multi-stage production Dockerfile</name>
  <files>backend/Dockerfile</files>
  <action>
Create `backend/Dockerfile` with a two-stage multi-stage build:

**Stage 1: Builder**
- Base: `python:3.13-slim-bookworm`
- Named: `builder`
- Install build dependencies: `gcc`, `libpq-dev` (needed for asyncpg and other C extensions)
- Create virtual environment at `/app/.venv`
- Set PATH to use venv
- Copy `backend/requirements.txt` and run `pip install --no-cache-dir -r requirements.txt`

**Stage 2: Runtime**
- Base: `python:3.13-slim-bookworm`
- Named: `runtime`
- Install only runtime system dependencies: `libpq5` (PostgreSQL client lib) and `curl` (for health check HTTP calls)
- Create non-root user: `groupadd -r appuser && useradd -r -g appuser appuser`
- Copy virtual environment from builder: `COPY --from=builder /app/.venv /app/.venv`
- Set PATH to use venv
- Copy application code: `COPY backend/app /app/app`
- Copy alembic: `COPY backend/alembic /app/alembic` and `COPY backend/alembic.ini /app/alembic.ini`
- Create uploads directory: `RUN mkdir -p /app/uploads`
- Set ownership: `RUN chown -R appuser:appuser /app`
- Switch to non-root user: `USER appuser`
- Set WORKDIR to `/app`
- EXPOSE 8000 (documentation only)
- No CMD -- docker-compose provides the command (API vs worker)

Add comments explaining:
- Why no CMD (single image, dual entrypoint pattern)
- API command: `uvicorn app.main:app --host 0.0.0.0 --port 8000 --workers 2`
- Worker command: `arq app.workers.worker_settings.WorkerSettings`

Do NOT use Alpine base (project uses pandas, asyncpg, openpyxl with C extensions -- musl libc causes issues).
Do NOT use shell form for any RUN commands that could be exec form.
  </action>
