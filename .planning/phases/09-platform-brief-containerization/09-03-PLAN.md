**Networks:**
- `backend`: driver bridge, `internal: true`

Note on `internal: true`: This prevents containers on this network from reaching the internet AND prevents external access to these containers. The API container will need outbound access for OpenAI API calls and database connections.

IMPORTANT CORRECTION: `internal: true` blocks ALL outbound traffic from containers. The API and worker need to reach:
- OpenAI API (external internet)
- PostgreSQL (platform-provided, external to Docker)

Therefore, we need TWO networks:
- `backend-internal`: `internal: true` -- for Redis (no internet needed)
- `backend`: standard bridge -- for API and worker (need external access for DB + OpenAI)

Actually, re-reading the CONTEXT.md: "Backend services on internal-only network -- not publicly reachable." The concern is that backends are NOT reachable from outside, not that they can't reach outside.

Docker's `internal: true` prevents BOTH directions. Since API and worker need outbound internet, we should NOT use `internal: true`. Instead, backend isolation is achieved by NOT mapping ports to the host (no `ports:` key on prod services). The platform GSD will handle network isolation at the infrastructure level.

FINAL APPROACH:
- Use a standard bridge network named `backend` (no `internal: true`)
- Do NOT expose ports on prod services (no `ports:` key) -- this means they're only reachable within Docker's internal network
- The platform's reverse proxy (Next.js) will connect to the API via Docker networking or the platform will configure network access
- Document in the platform brief that port mapping is intentionally omitted

Dev services (postgres, pgadmin) still expose ports for local development.
Redis does NOT expose ports in any profile (accessed via Docker networking).

  <name>Task 2: Create GitHub Actions CI workflow for Docker image publishing</name>
  <files>.github/workflows/docker-publish.yml</files>
  <action>
Create `.github/workflows/docker-publish.yml` for building and pushing the Docker image to ghcr.io.

**Trigger:** Push to `main` branch only.

**Environment variables:**
- `REGISTRY`: `ghcr.io`
- `IMAGE_NAME`: `${{ github.repository }}` (auto-lowercased by GitHub context)

**Job: build-and-push**
- Runs on: `ubuntu-latest`
- Permissions: `contents: read`, `packages: write`, `attestations: write`, `id-token: write`

**Steps:**
1. **Checkout repository** - `actions/checkout@v5`
2. **Set up Docker Buildx** - `docker/setup-buildx-action@v3`
3. **Log in to GitHub Container Registry** - `docker/login-action@v3` with registry, username (`github.actor`), password (`secrets.GITHUB_TOKEN`)
4. **Extract metadata (tags, labels)** - `docker/metadata-action@v5`
   - Images: `${{ env.REGISTRY }}/${{ env.IMAGE_NAME }}`
   - Tags:
     - `type=sha` (git commit SHA)
     - `type=raw,value=latest,enable={{is_default_branch}}` (latest on main)
5. **Build and push Docker image** - `docker/build-push-action@v6`
   - Context: `.`
   - File: `backend/Dockerfile`
   - Push: `true`
   - Tags: from metadata step
   - Labels: from metadata step
   - Cache from: `type=gha`
   - Cache to: `type=gha,mode=max`
6. **Generate artifact attestation** - `actions/attest-build-provenance@v2`
   - Subject name: `${{ env.REGISTRY }}/${{ env.IMAGE_NAME }}`
   - Subject digest: from build step
   - Push to registry: `true`

Create the `.github/workflows/` directory if it doesn't exist.

Name the workflow: "Build and Publish Docker Image"
