  <name>Task 1: Create session management and Data Access Layer</name>
  <files>
    frontend/src/lib/schemas.ts
    frontend/src/lib/session.ts
    frontend/src/lib/dal.ts
    frontend/src/middleware.ts

  <action>
1. Create `frontend/src/lib/schemas.ts`:
   - Zod schemas matching backend Pydantic models
   - signupSchema:
     - name: min 2 chars
     - email: valid email
     - password: min 8 chars, at least one letter, at least one number
     - confirmPassword: must match password
   - loginSchema:
     - email: valid email
     - password: min 1 char (let backend validate)
   - Include type exports (SignupInput, LoginInput)

2. Create `frontend/src/lib/session.ts`:
   - Use jose library for JWT operations
   - SESSION_SECRET from env (with fallback for dev)
   - encrypt(payload: SessionPayload) -> Promise<string>
   - decrypt(token: string) -> Promise<SessionPayload | null>
   - getSession() -> Promise<SessionPayload | null>
     - Get 'session' cookie
     - Decrypt and return payload
   - setSession(token: string) -> Promise<void>
     - Set 'session' cookie with httpOnly, secure, sameSite=lax
     - maxAge: 7 days (604800 seconds)
   - clearSession() -> Promise<void>
     - Delete 'session' cookie

   Note: The JWT from FastAPI is stored directly in the cookie. We use jose to verify on frontend for middleware.

3. Create `frontend/src/lib/dal.ts` (Data Access Layer):
   - Use React's cache() for request deduplication
   - verifySession():
     - Get session from cookies
     - If no session, redirect to /login
     - Return { isAuth: true, userId }
   - getUser():
     - Verify session first
     - Fetch user from backend API (/auth/me)
     - Return user data

4. Create `frontend/src/middleware.ts`:
   - Define public paths: /login, /signup, /forgot-password, /reset-password
   - matcher config to exclude api, _next, static files
   - If path is public, allow through
   - If path is protected (dashboard, etc), check for session cookie
   - If no session cookie, redirect to /login
   - If session exists, allow through (optimistic - DAL does real check)

Use Pattern 1 and Pattern 2 from 01-RESEARCH.md. Middleware is optimistic; real auth check happens in Server Components via DAL.
  </action>
  <verify>
1. Start frontend dev server
2. Navigate to http://localhost:3000/dashboard (should redirect to /login)
3. Navigate to http://localhost:3000/login (should load)
4. Check no TypeScript errors in console
  </verify>
  <done>
Session management utilities, DAL, and middleware created. Protected routes redirect unauthenticated users to login. Public routes accessible without auth.
  </done>
