## Technical Decisions from Research

1. **Stack**: Next.js 15 App Router + FastAPI + PostgreSQL 16 + async SQLAlchemy 2.0
2. **Auth approach**: Custom JWT (not NextAuth.js) since we only need email/password for v1
3. **Password hashing**: pwdlib with Argon2 (not bcrypt - GPU resistant, official FastAPI 2024 recommendation)
4. **RLS from day one**: PostgreSQL Row-Level Security implemented in initial migration (retrofitting is extremely difficult)
5. **Docker Compose**: One-command PostgreSQL setup for dev environment

<context>

## Mental Model

This is Phase 1 of a 7-phase project to rebuild a Streamlit prototype into a production SaaS. The goal is to establish the foundational architecture that all future phases build upon.

**What we're building:**
- Modern full-stack auth system with Next.js frontend + FastAPI backend
- Multi-tenant architecture with PostgreSQL RLS (even though v1 is team-only, we're building the foundation for future multi-tenancy)
- Dev environment that "just works" with Docker Compose

**Critical insight from research:**
PostgreSQL RLS must be implemented NOW in the initial migration. Retrofitting RLS after data exists is extremely painful and error-prone. Even though v1 is single-tenant, we're implementing multi-tenant RLS from the start.

**Why 4 plans?**
- 01-01: Foundation (scaffolding, can't parallelize - everything depends on it)
- 01-02 + 01-03: Core auth (backend API + frontend UI, can parallelize - no file conflicts)
- 01-04: Polish (admin settings + dev seeding, depends on both backend and frontend being ready)

**User preferences from context discussion:**
- Auth should feel "modern and professional (SaaS-grade, not prototype)"
- Dev mode should "just work" with minimal setup
- First user automatically becomes admin (controls OpenAI API key)
- Hardcoded dev credentials: admin@example.com / password123

</context>
